## Описание работы программного кода
🟦=>🟩=>🟨=>🟪
    
    🟦main: 
        -читает аргументы запуска (flag = {mode, host, port, username})
        -если mode == "server", запускает функцию runServer из файла server.go
        -если mode == "client", запускает функцию runClient из файла client.go


    🟩runServer (host,port):
        -запускает сервер на заданном адресе с помощью net.Listen 
        -запускает goroutine "handleConnection" для каждого соединения (клиента)


    🟨handleConnection(conn):
        -вызывает "handleFirstRequest" для чтения и сохранения ник и публичного ключа, потому что первый запрос от любого клиента содержает "username" и "publicKey".
        -сообщает всем клиентам о новым соединении (Broadcast)
        -начинает цикл, чтобы слушать все запросы (Request) от этого соединения.
        -добавить defer для завершения соединения

    🟪handleMessage(sender, message):
        -Эта функция проверяет, какой (Request.Method) клиент запросит из 3 методов:
            - BROADCAST: Отправить всем сообщение. В этом случае, поле Params в Request содержает Message(Sender,ContentContent,Message_TypeType="send_broadcast")
            - PRIVATE: Отправить определенному клиенту(Recipient) сообщение. В этом случае, поле Params в Request содержает Message(Sender,Recipient,ContentContent,Message_TypeType="send_private")
            - REQUEST_PUBLIC_KEY: Запросит публичный ключ определенного клиента, сохранненый у сервера. Этот публичный ключ нужнен для асимметричного шифрования (Crypto_box/Nacl)
        -После упешного отправления сообщение, сервер отправляет тот же сообщение отправителю, чтобы утверждать, что сообщение передано другим.
        -Перед отправлением Message клиетам, сервер добавляет timestamp в Message. Таким образом сервер решает время сообщений, чтобы сообщения были синхронны для всех клиентов
            
    🟩runClient(host, port, username)
        -генерирует ключи
        -определяет строку адреса из host и port
        -начинает соединение (net.Dial) к определенному адресу через протокол TCP
        -начинает gorountine receiveMessages, чтобы слушать все поступающие сообщения (8 типов сообщений):
            -MessageTypes[0]: //client_online: Это сообщение содержит данные клиента, который зашел в сеть. ClientInfo(username,publicKey). Эти данные будут сохраннены у всех клентов, которые получили, в их contactBook для того, чтобы было не надо запросить данные получателя, каждый раз хотят отправить личное сообщение.
            -MessageTypes[1]: //client_offline:Это сообщение содержит данные клиента, который вышел из сети. При этом сообщении клиенты, которые получили его, удаляют вышевшего клиента из их contactBook.
            -MessageTypes[2]: //send_broadcast:Это сообщение содержит публичное сообщение от другого клиента. При этом сообщении на консоле других клиентов появится сообщение.
            -MessageTypes[3]: //success_broadcast: Это сообщение содержит публичное сообщение от самого получающего клиента. Клиент получает это сообщение после того, как он успешно отправил всем то же сообщение.
            -MessageTypes[4]: //send_private: Это сообщение содержит личное сообщение от другого клиента. При этом сообщении только на консоле получавщего клиента появится сообщение. Это сообщение было шифрованно у отправителя, поэтому на сервер нельзя читать настоящее содержание. Расшировка идёт у получателя. 
            -MessageTypes[5]: //success_private: Это сообщение содержит личное сообщение от самого клиента. Клиент получает это сообщение после того, как он успешно отправил личное сообщение. Это сообщение было шифрованно у него, поэтому на сервер нельзя читать настоящее содержание. Это значит, сообщение сначала от этого клиента отправилось через сервер к получателю, и потом из сервера обратно к отправителю. Этот способ гарантинрует,что сообщения появляются, потому что сервер их распределяет, а не потому, что клиенты вводит сообщения на своем консоле, не зная отпралилось ли свое сообщение. 
            -MessageTypes[6]: //error: Клиент получает ошибку, если сервер его сообщение не удалость передать, или получатель не найден
            -MessageTypes[7]: //public_key_of_client: Это ответ сервера на запрос REQUEST_PUBLIC_KEY. Клиент получает публичный ключ других клиентов в при этом типе сообщения

        -запускает функцию sendMessage, чтобы читает сообщние у клиента на консоле, и его отправляет на сервер
        
    🟨СreateRequest(method, params): Создать запрос, отпраляется от клиента в сервер.

### Модель шифрования/расшифрования Nacl:
#### А отправляет B сообщение (Пакет: шифрованное сообщение, X_random_number)
    ⬜ шифрования (А):  Шифрорать сообщение с Public_Key_B_[32]byte + Private_Key_A_[32]byte + X_random_number[24]byte 
    ⬜ X_random_number[24]byte гарантирует, что шифрованные сообщения всегда разны, даже если их настоящие содердания одинокавы
    ⬜ расшифровки (B): Расшифрорать сообщение с Public_Key_A_[32]byte + Private_Key_B_[32]byte + X_random_number[24]byte
